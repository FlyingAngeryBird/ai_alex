# R1 内容备份、恢复预检与诊断入口

变更 ID：DEC-R1-DATA-026。父检查点 `1b294e7`。依据：最终 PRD F11d、5.1、G1/G5，实施附件12.3及14.6，P05 数据/诊断分层。仅修改独立 R1 工作树；旧版代码和数据不写入。SQLite10、注册资产2.5.1不变，没有新增模型 Prompt、Skill 或工具权限。

## 本批实现

1. P05设置增加折叠「数据与诊断」和历史入口，展示实际本地数量。用户可经系统文件对话框导出完整内容备份、选择备份预检、核对类型/数量、明确确认恢复并重启。取消文件对话框不算成功；恢复确认只表示已受理，实际完成在重启后读取结果。
2. 类型化IPC仅接受用户界面入口。恢复票据绑定窗口、冻结所选文件的独立快照、五分钟期限和当前数据修订。其他窗口、伪造确认、预览后数据变化、迟到文件选择、关闭面板与取消都不能越过确认。重复确认同一票据不会生成另一恢复动作。
3. 备份包含普通内容、非密钥设置和删除元数据，不包含安全凭据文件、原始录音或播放缓存。旧迁移的原始JSON从导出副本去除并VACUUM，不改原库回退资料。临时文件预建为0600，导出改为独立SQLite DELETE journal，不留下WAL；目标文件已存在时拒绝覆盖。
4. 恢复先验证schema、完整性和外键。实际替换只在任务/音乐/提取及备份操作排空、主连接关闭之后执行。暂存副本迁移并合并当前删除抑制、更正记录，保留当前自动记忆授权与设备/安静偏好；不覆盖凭据。源数据库可能含已提交WAL页，使用一致性快照而非仅复制主文件。替换前保存当前完整副本，失败保留当前数据库。重启后读取独立的成功/失败结果文件。
5. 诊断为用户主动导出的JSON，只包含版本、配置是否填写、配置修订、服务检测历史状态/错误码、白名单阶段与数值时间、提交回执时间/状态。无聊天正文、事件payload、原始音频、密钥、用户文件路径或自动上传。不同进程时钟不直接相减，缺阶段不补造。

## 验证与边界

- 完整自动化回归：82文件500项通过，生产构建通过（保留既有bundle size提示）；涉及实际SQLite备份/恢复、WAL、旧版本迁移、遗忘/更正保护、授权保留、CAS、窗口票据、取消/退出排空、诊断字段过滤及IPC白名单。随后仅增退出finally保护与清理容错，4文件21项关联检查、资产/合同校验与生产构建再次通过。
- 曾出现一项测试误报：测试自身用可写数据库打开导出文件并切换journal模式，之后比较原始字节。改为只读检查后，15项备份/恢复关联检查通过。生产代码没有为此放松“不得覆盖已有目标文件”的断言。
- `node scripts/check-data-restart.mjs`：加载正式main/preload和构建页面，空隔离目录、合成便签/记忆，无服务配置、不开麦；系统文件选择替换为测试端口，业务服务不替换。实际经过确认IPC→服务排空→关闭数据库→离线恢复→`app.relaunch()`→新进程读取结果。覆盖前2条事项/备份1条，重启后1条；备份中的旧记忆未复活，当前勿扰保留，覆盖前副本存在。此为正式主进程恢复测试，**不是完整真人界面/安装验收**。
- CUA正式窗口：展开数据/诊断、读取实际数量、通过系统保存对话框导出备份与诊断、系统选择备份后看到11类覆盖数量及范围。实际文件0600、备份schema10且integrity_check=ok。诊断首个保存路径被系统当作文件名，核验后移到临时目录，未覆盖用户文件。
- CUA在恢复确认处出现noWindowsAvailable/timeout；重置通道后可读预览，但确认按钮点击没有取得可验证回执。该实例后续正常退出信号亦未产生完成事件，测试实例被终止，原数据和备份保留；没有据此声称UI恢复成功。此界面/窗口事件问题继续列为未验收项，需排查，不能以主进程测试代替。

## 运行与回退

```sh
npm run build
npm test
node scripts/check-data-restart.mjs
node scripts/check-desktop-ui.mjs --keep-data
```

所有脚本都在独立临时目录使用合成/空数据。`--keep-data`用于实际重启核验，防止父进程在旧进程退出后删除新进程仍需的数据；保留的测试目录以日志输出为准，只在相关进程退出后清理。恢复失败不改写当前凭据或旧工作目录。代码回退至父检查点前完全退出R1；本批未提升schema。
