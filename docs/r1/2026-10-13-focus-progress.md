# R1 专注计时开发记录（G3 未通过）

changeId：DEC-R1-FOCUS-006。依据：最终 PRD v1.0 第 3.4 节、F07d 与资产 focus 工具合同。

## 实现与版本

- 主进程持有独立 Focus 服务；清醒时按单调时钟计时，SQLite 保存剩余量与状态。每段有 focusId/version；开始及控制通过 actionId 幂等回执，旧版本拒绝覆盖。
- 同时最多一段 running/paused 专注，数据库唯一索引再次约束；重复开始不覆盖旧段。暂停/提前结束分别为 paused/stopped，自然归零才 completed。默认 25 分钟，输入 60–10800 秒。
- 睡眠事件先保存清醒时间后暂停，唤醒不自动继续；服务重启把运行段恢复为暂停。彻底退出前保存暂停。单实例应用锁避免第二进程同时持有同一 R1 数据库计时。
- 事项侧栏和待办编辑弹窗提供入口，共用开始弹窗与顶部轻量状态条；切页、界面重载不拥有或重置计时。默认完成不控制音乐；用户勾选结束暂停时冻结所选 trackKey，完成事件只在实际当前曲目相同且播放中时请求暂停。
- R1 数据 schema 升为 3，新增结束音乐规则/曲目字段和活动段唯一索引。v1/v2 自动升级，旧备份在恢复副本升级后再应用删除抑制，原备份不变。源码回退必须使用兼容 schema 3 的 R1 数据副本；旧版应用仍使用自己的数据目录，不降级覆盖。

## 证据

- 全量测试：47 文件、263 项通过；构建通过。领域测试覆盖单调计时、暂停不扣时间、自然完成仅一次、停止不完成、幂等、版本冲突、单活动段、睡眠/重启恢复、时长边界及冻结歌曲身份。
- 迁移用例保留 v2 剩余量及状态，数据库拒绝第二活动段；旧备份恢复用例证明 source 文件字节不变、恢复副本升级成功。
- 独立 Electron 测试入口 `tests/fixtures/focus-runtime.mjs` 使用临时数据目录、正式 preload/IPC/Focus 服务与正式 Focus 组件；不导入生产 main，不读取用户配置/资料。
- 实际操作：默认值 25 分钟；设为 1 分钟开始，focusId 固定；暂停时 remainingSec=51、version=2；继续后 version=3；界面重载后同一 focusId、remainingSec=32；自然完成 remainingSec=0/state=completed/version=4，并出现完成提示。第二段 25 分钟提前结束得到 state=stopped/version=2、剩余 1482 秒，没有标为 completed。
- 已目视检查弹窗和状态条。独立测试窗口内的 JSON 仅为测试观察，不进入正式 UI。
