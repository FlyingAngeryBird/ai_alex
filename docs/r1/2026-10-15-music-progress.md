# 音乐统一状态、实际回执与持久化

变更：DEC-R1-MUSIC-022 / DEC-R1-MUSIC-023。依据：最终 PRD 3.5、F08a–F08f、V19–V21 及现有 R1 原型音乐资料库、队列、反馈、音量与进度入口。父检查点 `de8b600`。仅在独立 `codex/seamo-r1` 工作树开发；未向旧工作目录写入，保留其已有未提交修改。

## 本批代码路径

1. 主进程 R1Music 拥有曲目、时钟、playerVersion、queueVersion、基准音量和实际设备身份。解析到 URL 只进入缓冲；当前设备以 nonce、playbackRequestId、commandId 确认后才产生播放成功回执。旧设备、旧资源、迟到 play Promise 不能恢复已经暂停或退出的音乐。
2. 文字主会话、原生会话工具、后台 Task 与界面共享领域服务。模型须加载所需 Skill，并观察实际曲目与当前版本；猜 ID、猜版本、扩大授权被拒绝。重复 call_id 复用实际行动，未完成的同一任务调用不重复播放；未知结果禁止盲重试。任务或轮次已取消时仍保留已经发生的真实设备回执，旧模型续答被拒绝。
3. 同曲换源限定相同完整曲名、歌手及已知时长范围，保留 Live/混音等版本区别，最多三次资源尝试；回执使用实际成功来源。失败不换另一首来宣称完成。失败后的显式继续会重新解析资源。繁简歌手名及别名未做自动等价映射。
4. 队列具有稳定 entryId 和独立 CAS 版本；收藏、like/dislike/skip、反馈场景与来源独立保存。跳过不抹去已有明确反馈，也不构成永久封禁；明确点名歌曲不因 dislike 消失。临时查询和换源不读取普通反馈；临时持久化须由界面明确确认，临时任务和回执不写 SQLite。
5. 实际 HTMLAudioElement 经类型化桥接执行播放、暂停、继续、seek、音量、结束和退出。明确选曲不自动把搜索结果全塞入队列；队列末尾停止。原型已有的“退出播放”释放当前播放器，独立队列保留；专注结束只暂停当初明确绑定的曲目，不能暂停用户后来选择的歌。
6. 原型资料库接真实搜索、队列、收藏和反馈；未播放时显示空搜索框，选择曲目后收起资料库。可用状态未知时显示“待播放验证”，封面失败回退占位，不生成歌词。临时保存弹窗有取消、焦点约束与恢复。未完成新的 CUA 点击或同尺寸视觉验收。
7. 降音继续使用真实语音活动与助手实际播音事件，独立于基准音量，不调用 play 恢复声音。用户音量、静音、暂停优先。实际音频分析和 LRC 时钟继续复用；本批没有完成实际三类音源听测，也没有证明所有 PTT 回退路径均产生正确降音活动。
8. 音源搜索并行且按固定来源顺序合并；每源结果按请求数量限制，避免服务忽略 count 后对几十张封面同时请求。请求有超时和退出中止。界面音频时钟不触发每次进度都读数据库或广播完整资料库。退出先中止生成/设备/任务，等待媒体执行及其回执落地再关闭 SQLite。

## 真实模型与音源核验

模型用例只发送合成歌曲、合成用户指令和独立内存数据库；音频设备明确为模拟。没有发送用户历史、没有输出凭据。完整机器记录见 [证据 JSON](evidence/2026-10-15-music.json)。

| 核验 | 实际结果 |
| --- | --- |
| 资产 2.5.0 首次点歌 | Ark 把只读 music_search 填进 requiredActions，违反仅允许副作用的 Schema；拒绝执行，播放器仍 idle |
| 注册资产修正 | PR03 / SK05 明确即时点歌的加载、搜索/状态观察和实际开播顺序；委托 requiredActions 不填只读工具。不增加路由模型，不扩大预算 |
| 最终资产 2.5.1 点歌 | load_skill → music_get_state + music_search → music_play → 真实模型答复；模拟设备确认后为 playing，6690ms |
| 音量 30% | get_state → set_volume → 答复，实际领域基准为 30，3687ms |
| 仅提到歌曲 | 无工具调用，无新增设备命令，3539ms |

三例共 8 次真实 Ark 请求，5 条普通音乐工具回执。这是文字工具链路样本，**不是实际听音、原生语音首响或全量语义成功率**。首次失败保留，没有用 fixture 结果覆盖真实模型失败。

## 验证和版本保存

- 自动化覆盖领域设备确认、竞态、跨源身份、队列事务、收藏反馈重启、临时隔离、实际前端音频桥接、主会话/任务幂等与取消、未知回执、退出回执排空、GUI IPC 与 schema7→8 快照回退。
- 最终全量回归：77 个测试文件、472 项通过；生产构建通过，保留 Vite 现有 bundle size 提示。自动化设备与音源是 fixture，不能据此声称可实际听歌。
- 静态资产：10 Prompt、6 Skill、38 业务工具、3 内部工具、14 Schema、21 行为案例、59 哈希文件；16 合同样例通过。
- 资产 release/schema 2.5.1，PR03 1.3.2，SK05 1.1.1；其他 Prompt 版本不变。music_get_state 增加可选真实 feedback；模型工具别名总数不变，UI 退出使用通用 music.exit Receipt。
- SQLite schema8：音乐设置、查询历史、反馈 scene/source_ref；升级前生成并核验 schema7 快照。旧 JSON 只读导入一次，旧资料先导入再初始化音乐缓存；新保存的队列/收藏剔除临时 audioUrl/LRC。旧包拒绝直接打开 schema8，不原地降级。
- 回退使用父提交 `de8b600` 和隔离的升级前数据快照；不要把旧快照覆盖到现在的用户数据。此为开发检查点，不创建 G4 通过标签、正式 Release 或已安装验证的旧版包。GitHub 推送凭据尚未确认就绪。
