# R1 后台循环与真实便签写入进展

日期：2026-10-14。changeId：DEC-R1-TASK-RUNNER-009。对应 F03、F06a/F06b、F09、F10b。父检查点：`26b2456`。**G0/G3 与完整 R1 验收仍未通过。**

## 实现

- `R1TaskRunner` 已接主进程，监听 Supervisor 受理/继续，受理同步返回后才在后台调用 M02。一次只运行一个执行循环；暂停等待当前请求结束再落安全点，旧目标迟到结果不发布。停止语音不控制普通 Task。
- 每次决策都从 Supervisor 获取最新 TaskInput、权限与预算，经注册 PR04 最终请求边界；目标修改附注册 PR08。请求使用 Ark Responses、原 call_id 配对、store:false。工具暴露取可信委托与实际已实现工具的交集，未实现操作不会被当作可调用能力。
- 实现工具目前为 read_file、write_todos、notes_create。创建便签/待办使用真实 R1Items；保留来源，原文模式不删除前后空白；暂不实现其余领域工具，未宣称创建提醒、播放器动作或搜索可走该循环。
- 内部计划/Skill 状态、SQLite 对象与真实回执同事务提交。输出校验失败回滚对象和任务内存状态；计划事件在提交后发送，不先显示未提交的成功。
- 同一 run 下相同原协议 call_id 重试复用 actionId/实际回执；参数或工具变了则拒绝。不同协议 call_id 是不同动作，不把正文相同的两次明确创建误合并。该机制不等于跨重启完整框架恢复；旧写入不确定时先核回执并停止，不自动重放。
- 临时 Task 仍仅内存；notes_create 的持久化确认来自可信调用方，不是模型参数或渲染层可自授字段。确认保存的 Item/Receipt 可保留，Task 原文和计划不写 SQLite。
- 活动预算到限，保存实际执行记录与部分结果，停止自动请求。用户明确继续后才从受理时冻结的预算重新开始一个窗口；暂停没有耗尽预算时不补额度。恢复先核对既有动作/真实回执，unknown 或缺回执阻止新模型请求。
- 必要领域动作由可信调用方在受理时声明，写入检查点/受理指纹及 TaskInput 程序资料；completed 必须包含足够实际成功回执。工具授权是可做范围，必要动作是完成条件，两者分别验证。M02、网页和最终 JSON 不能修改该条件。主会话尚未接入此可信委托链路。
- TaskDraft 无效时仅一次无工具 PR10，计入模型预算；修复仍经原 Supervisor 检查，不再次调用写工具。修复输入携带实际 actionId→entityId/状态/版本证明及合法 Artifact 基准，不发送未注册业务提示词。修复失败保留已写实体，拒绝发布成功。
