## 开发前固定的实施规则

- 每个 UI 入口先对照原型位置、最终 PRD 行为和真实领域接口；无真实状态时只展示可解释的空/错误/未配置状态，不移植模拟成功。
- 一个变更必须记录功能 ID、用户可见差异、状态及数据迁移、风险、验收用例与回退办法；实现后核对原型截图与真实交互。
- 不从原型复制业务脚本、fixture、假进度、虚构地点或歌曲；可复用视觉结构、组件语义和交互顺序。
- G0 供应商、原生实时语音、音乐源、macOS 权限和性能基线未验证时维持未通过状态；若需改变可见体验，先按 PRD 更新差异决定。
- G0–G5、41 项 F、A01–A60、V01–V24 均不能凭构建或 mock 通过。无阶段通过标签、正式 Release 或“R1 已完成”表述。
