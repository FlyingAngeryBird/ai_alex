# 灵粒 MVP 设计规格

日期：2026-06-27
状态：等待用户审核
平台：macOS 第一版

## 1. 已确认的产品目标

灵粒是一款 macOS 桌面 AI 语音伙伴应用。用户打开应用后，会看到一个柔和、有艺术感、持续呼吸律动的动态粒子球。用户可以直接开口说话，灵粒自动检测语音并进入对话；同时保留按住空格键说话、松开后发送语音的手动模式作为兜底。灵粒会识别语音、理解上下文，并用文字和语音回复用户。

应用在 MVP 阶段保留当前会话内的短期记忆。用户可以连续聊天，灵粒需要理解前后文，而不是每一句都当成孤立问题。

当用户表达播放音乐的意图时，灵粒会识别该意图，使用 Apple Music 搜索音乐，进入沉浸式音乐播放页，并让粒子球根据音频或播放状态继续律动。

## 2. 已确认的产品范围

MVP 必须包含：

- macOS Electron 桌面应用。
- Vue 3 前端界面。
- Three.js 动态粒子球。
- 自动监听语音对话模式：用户开口说话时自动进入聆听，停顿后自动发送识别。
- 按住空格录音，松开后发送识别，作为手动兜底交互。
- 火山引擎 ASR 语音识别。
- 火山方舟 / 豆包大模型多轮对话。
- 火山引擎 TTS 语音合成和播报。
- Apple Music MusicKit 作为主要音乐服务。
- 音乐搜索、播放、暂停/继续、返回对话。
- 当前会话内的短期记忆。
- 每个用户操作都有明确的加载、成功、失败反馈。

MVP 不包含：

- Windows 打包。
- 除 Apple Music 授权外的用户账号系统。
- 应用重启后仍保留的长期记忆。
- 每首歌都保证有逐句同步歌词。
- 音乐收藏、歌单管理、喜欢歌曲、基于历史偏好的长期推荐。

## 3. 关键产品决策

### 3.1 第一版只做 macOS

第一版只在 macOS 上开发和验收。等核心体验稳定后，再考虑 Windows 版本。

### 3.2 AI 链路统一使用火山引擎

MVP 的 AI 链路使用火山引擎：

- ASR：支持两层能力。第一层保留录音文件识别作为稳定兜底；第二层接入火山流式 ASR / 实时语音能力，用于自动监听对话。
- LLM：使用火山方舟 / 豆包对话模型。
- TTS：使用火山引擎语音合成，如果流式 TTS 接入稳定，则优先使用流式方案。

第一版分阶段落地语音体验：先保证“按住说话、松开发送、AI 回复”的可靠体验，再实现“开口自动监听、停顿自动发送”的实时语音模式。实时打断、全双工连续插话和实时字幕属于增强项，不阻塞第一版闭环。

### 3.3 实时语音对话模式

实时语音模式是灵粒的目标交互形态。用户打开“自动聆听”后，不需要按住空格；系统通过麦克风音量、语音活动检测和流式 ASR 判断用户是否开始说话。检测到稳定语音后，粒子进入 `listening`；检测到停顿或一句话结束后，系统自动提交文本给 LLM，并进入 `thinking` 和 `speaking`。

实时语音模式的 MVP 验收边界：

- 用户可以在界面中开启或关闭“自动聆听”。
- 开启后，用户开口说话能触发聆听状态。
- 用户停顿后，系统能自动结束本轮输入并发送识别结果。
- AI TTS 播放期间默认暂停自动监听，避免把 AI 自己的声音再次识别成用户输入。
- 自动监听失败时，用户仍可使用按住空格模式完成对话。
- MVP 不要求打断 AI 正在说的话；打断能力放到后续增强。

### 3.4 音乐主链路使用 Apple Music

Apple Music MusicKit 是 MVP 的主要音乐服务。应用不依赖任何非官方网易云音乐 API。

Apple Music 的产品限制需要提前接受：

- 用户可能需要完成 Apple Music 授权。
- 完整播放可能依赖用户的 Apple Music 订阅和所在地区。
- 部分歌曲可能无法播放。
- 官方逐句歌词能力不一定能稳定开放给第三方应用。

因此，逐句同步歌词是优先能力，但不是 MVP 阻塞项。如果拿不到歌词，沉浸播放页需要降级展示歌曲信息、封面、播放进度和灵粒的推荐理由。

## 4. 技术架构

应用分为三层：

1. 前端渲染层。
2. Electron 主进程本地后端。
3. 外部服务层。

### 4.1 前端渲染层

技术：

- Vue 3
- Vite
- Three.js
- Web Audio API

职责：

- 渲染粒子球。
- 展示聊天界面。
- 管理录音交互状态。
- 管理自动聆听开关、语音活动状态、空格键按下和松开。
- 展示沉浸式音乐页。
- 控制音乐播放 UI。
- 在歌词可用时展示歌词。
- 在可访问音频数据时分析音频频谱，驱动粒子球律动。

前端不能读取云服务密钥，也不能直接调用火山引擎接口。

### 4.2 Electron 主进程

职责：

- 管理桌面窗口生命周期。
- 读取环境变量。
- 处理前端 IPC 请求。
- 调用火山引擎 ASR / LLM / TTS。
- 处理 Apple Music 授权和音乐服务桥接。
- 管理临时音频文件和缓存。
- 管理当前会话记忆。
- 处理意图路由。
- 统一错误格式。

主进程是本应用的“本地后端”。

### 4.3 外部服务层

外部服务包括：

- 火山引擎 ASR。
- 火山方舟 / 豆包 LLM。
- 火山引擎 TTS。
- Apple Music MusicKit / Apple Music API。

所有外部服务都必须封装在本地 provider 接口后面，方便后续替换。

## 5. 主要模块

### 5.1 前端模块

- `ParticleSphere`：渲染粒子球，并接收状态和音频输入。
- `ConversationView`：展示聊天消息和交互状态。
- `RecordingController`：管理按键录音 UI 状态，并调用 IPC。
- `MusicImmersiveView`：展示音乐播放页、封面、进度、歌词和返回控制。
- `AudioAnalyser`：把可访问的音频转成音量/频率数据，驱动粒子球。

### 5.2 主进程模块

- `asrProvider`：把录音发送给火山 ASR，返回识别文本。
- `llmProvider`：把消息发送给豆包模型，返回结构化 AI 回复。
- `ttsProvider`：把 AI 回复文本转换成可播放语音。
- `musicProvider`：搜索和播放 Apple Music 内容。
- `memoryService`：保存当前会话最近的对话上下文。
- `intentService`：解析大模型结果，并路由音乐等意图。
- `audioCache`：保存临时录音和 TTS 音频。
- `ipcHandlers`：向前端暴露安全的能力调用。

## 6. IPC 能力契约

前端只能通过 IPC 调用主进程能力。

需要暴露的能力：

- `voice.startRecording`
- `voice.stopAndTranscribe`
- `voice.startRealtime`
- `voice.stopRealtime`
- `voice.setAutoListen`
- `chat.sendMessage`
- `tts.speak`
- `music.authorize`
- `music.search`
- `music.play`
- `music.pause`
- `music.resume`
- `music.getPlaybackState`
- `app.getRuntimeState`

每个 IPC 响应必须使用统一格式：

```ts
type AppResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: { code: string; message: string; recoverable: boolean } };
```

## 7. 对话流程

1. 用户打开应用。
2. 粒子球进入 `idle` 待机状态。
3. 灵粒用一句温暖的开场白问候用户。
4. 用户开口说话，或按住空格键。
5. 前端进入 `listening` 聆听状态。
6. 自动监听模式下，系统检测到停顿后自动结束本轮输入；手动模式下，用户松开空格键。
7. 主进程把音频发送给火山 ASR；实时模式优先使用流式 ASR，手动兜底使用录音文件 ASR。
8. 前端进入 `thinking` 思考状态。
9. 主进程把识别文本和会话记忆发送给豆包模型。
10. 豆包模型返回结构化回复。
11. 如果是普通聊天，主进程调用 TTS，灵粒播报回复，粒子进入 `speaking` 状态。
12. 如果是音乐意图，应用搜索 Apple Music，并进入音乐流程。
13. 播报结束后回到 `idle`；音乐播放中保持 `playing` 状态。

## 8. 大模型输出契约

大模型需要尽量返回可路由的结构化 JSON。

普通聊天：

```json
{
  "reply": "温暖、自然、可播报的回复文本",
  "intent": "chat",
  "music": null
}
```

音乐意图：

```json
{
  "reply": "好，我给你找一首轻松一点的歌。",
  "intent": "play_music",
  "music": {
    "query": "轻松",
    "mood": "relaxed"
  }
}
```

如果模型返回了非法 JSON，应用不能崩溃。系统应当把它当成普通聊天文本处理，并记录一个可恢复的路由错误。

## 9. 粒子球状态

必须支持的状态：

- `idle`：缓慢呼吸，柔和自转。
- `listening`：变亮、加速、更敏感。
- `thinking`：粒子收拢、脉冲、略微紧致。
- `speaking`：根据 TTS 音频强弱变化。
- `playing`：根据音乐音频或播放状态律动。
- `error`：平静降亮，并展示可恢复提示。

粒子组件需要暴露简单输入 API：

```ts
setVisualState(state: ParticleState): void
setAudioLevel(level: number): void
```

## 10. 音乐流程

1. 大模型返回 `intent: "play_music"`。
2. 主进程检查 Apple Music 授权状态。
3. 如果未授权，前端引导用户完成授权。
4. `musicProvider.search(query)` 返回候选歌曲。
5. MVP 阶段默认选择最合适的可播放结果，通常是第一首可播放歌曲。
6. 前端进入 `MusicImmersiveView` 沉浸播放页。
7. 开始播放音乐。
8. 仅在官方能力可用时加载歌词。
9. 如果没有歌词，页面展示封面、歌曲信息、进度和灵粒推荐理由。
10. 点击返回按钮回到对话页，同时保留一个紧凑音乐播放器。
11. 紧凑音乐播放器提供暂停/继续，并支持重新进入沉浸播放页。

## 11. 分阶段验收门禁

### M0 工程底座

目标：建立干净的 macOS Electron 应用基础。

交付结果：

- Electron + Vue 应用可以启动。
- 目录结构清晰。
- 环境变量被 Git 忽略。
- IPC 可以完成一次测试通信。

验收标准：

- 应用可以在 macOS 打开。
- 前端无法访问火山引擎密钥。
- `.env` 不会被提交。
- `.superpowers/` 被忽略。

### M1 粒子 UI

目标：建立灵粒的核心视觉识别。

交付结果：

- 页面中央有柔和、有呼吸感、有渐变和状态切换的粒子球。

验收标准：

- 支持 `idle`、`listening`、`thinking`、`speaking`、`playing`。
- 状态切换肉眼可见且流畅。
- 当前目录中的粒子参考 HTML 作为视觉参考。
- 常见 macOS 笔记本窗口尺寸下，UI 不重叠、不溢出。

### M2 语音输入和 ASR

目标：把用户语音转换成文字，并支持手动和自动两种输入模式。

交付结果：

- 手动模式：按住空格键录音，松开空格键后调用火山 ASR 识别。
- 自动模式：开启自动聆听后，用户开口触发录音/流式识别，停顿后自动提交。

验收标准：

- 手动模式下，只有按住空格时才录音，松开空格后自动发送音频。
- 自动模式下，用户开口说话能进入聆听状态，停顿后自动发送本轮语音。
- TTS 播放期间自动监听暂停，避免回声自触发。
- 中文普通话可以返回可用文本。
- 失败时展示温和、可恢复的提示。

### M3 LLM 和会话记忆

目标：实现温暖、连续的多轮对话。

交付结果：

- 用户文本和最近会话上下文发送给豆包模型。
- AI 返回结构化结果。

验收标准：

- 连续 5 轮聊天不丢失前文背景。
- 回复语气温暖、自然，不机械。
- 音乐意图可以用结构化结果表达。
- 模型输出异常时应用不崩溃。

### M4 TTS 和说话状态

目标：让灵粒真正“说话”。

交付结果：

- AI 文本回复转换成语音。
- 语音自动播放。
- 粒子球跟随语音波动。

验收标准：

- 回复生成后能启动 TTS。
- 用户能听到回复语音。
- 播放过程中粒子球有明显音频响应。
- 播放结束后回到正确状态。

### M5 Apple Music 意图和搜索

目标：把音乐请求转换成 Apple Music 搜索结果。

交付结果：

- 音乐意图触发 Apple Music 搜索。
- 应用获取歌曲元数据和可播放状态。

验收标准：

- 用户说“播放一首轻松的音乐”可以触发音乐流程。
- 普通聊天不会误触发音乐。
- 未授权 Apple Music 时有明确引导。
- 歌曲不可播放时有明确提示。

### M6 沉浸音乐页

目标：完成第一版音乐体验。

交付结果：

- 音乐页展示歌曲信息、封面、进度、控制按钮，以及可用时的歌词。

验收标准：

- 播放、暂停、继续、返回都可用。
- 返回对话页后，保留紧凑音乐播放器。
- 粒子球能根据音频律动；如果拿不到音频数据，则使用优雅的播放状态律动兜底。
- 官方歌词可用时，支持歌词同步展示。
- 没有歌词不算 MVP 失败。

### M7 macOS 打包

目标：生成本地可运行的 macOS 应用。

交付结果：

- 应用可以打包，并在非开发模式下启动。

验收标准：

- 新环境配置 `.env` 后可以运行。
- 语音对话链路可用。
- 在 Apple 账号权限允许的情况下，音乐授权、搜索、播放链路可用。

## 12. 错误处理标准

每个用户可见错误都必须说明：

- 发生了什么。
- 用户能否重试。
- 是否有安全兜底方案。

必须处理的错误场景：

- 麦克风权限被拒绝。
- ASR 请求失败。
- LLM 回复失败。
- TTS 生成失败。
- Apple Music 未授权。
- Apple Music 订阅或地区不支持播放。
- 歌曲没有歌词。

## 13. 安全和隐私

- 火山引擎密钥只存放在 `.env`。
- `.env` 只由 Electron 主进程读取。
- 前端不能拿到任何云服务密钥。
- 录音和 TTS 文件只作为临时文件保存。
- MVP 阶段会话记忆只保存在内存中。
- MVP 阶段不落盘保存用户聊天记录。

## 14. 测试策略

每个里程碑都必须做人工验收。

自动化测试优先覆盖：

- Provider 返回结果标准化。
- 意图解析异常兜底。
- 如果存在官方歌词来源，则测试歌词解析。
- 会话记忆裁剪到指定轮数。
- IPC 返回格式一致性。

视觉验收必须覆盖：

- 粒子球状态切换。
- 主聊天界面布局。
- 沉浸音乐页布局。
- macOS 小窗口和大窗口尺寸。
