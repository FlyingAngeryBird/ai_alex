## 1. 本次交付与边界

这份原型回答：用户提出一句话后，在哪里看进展、得到什么结果、怎样继续修改，以及出错后如何恢复。

已提供六类能力的代表性交互，以及“查询 → 用户选择 → 保存 → 添加提醒”的连续委托。保留现有深色陪伴空间、粒子球主体和沉浸听歌方向，不改正式应用的语音、音乐或 Agent 逻辑。

**原型采用固定脚本与示例数据。能点击走通，不代表真实能力已经接通，也不代表 PRD 的 41 项功能、60 个验收场景已经通过。**

- 真实发生：浏览器内编辑、独立本地保存、收藏、事项状态修改、讨论稿下载。
- 模拟发生：语音输入、模型回应、查询进度与候选、歌曲播放时钟、歌词、提醒到期展示。
- 尚未发生：麦克风采集、云端推理、真实搜索、真实音频输出、系统通知、后台任务恢复。
- 不读取 API Key，不产生云端模型或音乐接口调用。字体和配图仍可能从 Google Fonts、Unsplash 加载；失败时保留字体与图片占位。

## 2. 如何打开

正在运行的预览：<http://127.0.0.1:59431/>。

已生成不依赖开发服务的单文件版本 `dist/index.html`；本目录的 `index.html` 配置了直接打开时跳转到它的行为。单文件产物已通过 HTTP 加载与交互检查，但浏览器测试工具禁止访问 `file://`，因此本轮未验证双击打开路径，评审优先使用上面的预览地址。

右上角“R1 交互原型”是评审入口，包含六条链路、连续委托和异常情形。建议先体验“查询、记事与提醒”，再逐项检查六类能力。

本地预览与单文件版是不同浏览器来源，演示数据不保证共享。“重置原型数据”只恢复这个原型的示例，不清理正式应用。

开发时从项目根目录运行：

```sh
npm run dev --prefix 'Seamo-AI语音助手/交互原型/R1'
npm run build --prefix 'Seamo-AI语音助手/交互原型/R1'
```

修改源文件后需要重新构建，单文件版才会更新。原型借用项目已有 Vue、Three.js 与粒子组件，不能把源码文件夹单独复制到别处视为独立开发项目；构建后的单文件可单独打开。

## 3. 界面结构与设计理由

| 位置 | 用户此刻的问题 | 原型采用的形式 |
| --- | --- | --- |
| 陪伴首页 | 我想说话，它有没有在听、在做？ | 保留粒子主体，最近三轮对话按需展开，长回复可展开全文，当前结果仅显示一次 |
| 顶部任务入口 | 我切到音乐或收起结果后，刚才的查询去哪了？ | 只在当前结果不可见时出现，可重新打开任务详情 |
| 右侧展开区 | 我想核对、修改或找回具体内容 | 记忆、事项和设置保持窄侧栏；搜索比较、长文编辑在宽窗口展开，窄窗口进入实色覆盖区并保留输入 |
| 音乐沉浸页 | 我想听歌，暂时不想管理任务 | 原有粒子、居中动态歌词、紧凑曲目信息；搜索与队列按需打开 |
| 底部输入 | 换个页面还能不能接着说？ | 首页与音乐页共用输入；搜索和讨论稿覆盖主区时，在展开区底部继续输入 |
| 窄窗口 | 内容是否仍可读、可操作？ | 导航移到底部，侧栏变为覆盖式详情，保留关闭入口 |

认知顺序是“和它交流 → 看这次结果 → 需要时展开细节”，而不是先学习一个工作台。

粒子直接复用 `src/components/ParticleSphere.vue`，本轮未改球体几何或音乐响应算法。原型仅提供模拟频段驱动，不能用它验证真实歌曲的节拍效果。

## 5. 连续委托：检验 Agent 体验

评审入口：右上角原型菜单 → “查询、记事与提醒”。

示例：“帮我查查周末安静的去处，选好后记下来，明晚8点提醒我。”

1. 首页接受委托，展示查询进展；用户仍可继续聊天。
2. 任务保留原始条件和已约定的实际提醒日期，不先替用户选去处。
3. 查询完成后过程收起；用户打开结果，可选列表或并排比较。
4. 用户先选中候选，再点击“选这个，记下并提醒”，保存所选对象并关联约定时间。
5. 首页出现结果；事项中可以继续编辑、改期或取消，重复保存不增加同一候选副本。
6. 没有给出提醒时刻时，先记下选定去处，再询问具体时间；不自作主张创建提醒。

这验证的是跨能力协作的产品行为，关联 A46 的部分意图。实际运行仍是脚本，不是自主规划，也不覆盖 A46 中的查证、局部续改和真实工具回执。

## 6. 异常与状态规则

- 停止回应与取消查询是两个动作。关闭侧栏不取消任务。
- 查询中修改条件会启动新的模拟请求，旧回调不能发布旧结果。
- 查询失败保留条件，重试后恢复；没有展示成“已成功查到”的假失败。
- 评审入口的“已保存，提醒失败”保留记录，仅将提醒标记为未完成；点击铃铛可单独重试。
- 连续委托缺少提醒时间时，输入框留空；过去时间不能保存为新提醒。
- 完成带提醒的待办时，同步取消提醒，并提供短暂撤销入口；删除带提醒的事项仍会先说明并确认。
- 临时对话不保存聊天、不读取长期记忆；显式保存记忆、候选或事项须先确认退出临时对话。
- 普通对话历史只保留原型最近 80 条消息，不等同于正式会话管理。
- 任务、播放进度、专注计时不会跨刷新恢复；记忆、话题、已保存事项、未保存讨论稿、收藏、设置和普通历史会保存。刷新后首页恢复最近一轮普通对话。

原型把提醒时间附在事项上，供流程评审。正式实现必须继续遵守 PRD 的 Task、Item、Reminder、Artifact 分离契约，不能照搬这个简化存储结构。

## 7. 相对旧版 PRD 的交互调整

以下原型建议已纳入最终 PRD v1.0 的产品行为口径；原型仍不等于真实功能通过。开发实施必须以最终 PRD 为准，并同步旧版机器可读 Schema 与验收用例。

| 原型建议 | 原因 | 最终口径 |
| --- | --- | --- |
| 记忆、事项、设置作为同一陪伴空间中的侧栏，而非每次整页切走 | 修改一个小内容不必离开对话 | 接受侧栏优先呈现；P03 至 P05 能力完整保留，窄窗口变覆盖层 |
| 点歌先在后台出现迷你播放器，主动点击才进入沉浸页 | 音乐陪伴不应打断正在进行的聊天 | 实际开播后保留当前页，用户主动进入沉浸页 |
| 删除带提醒事项时明确确认并一并取消 | 减少“事情删了、提醒还响”的意外 | 删除需确认，默认只删事项并保留提醒；可显式选择连提醒取消 |
| 常用设置先呈现称呼和声音，表达偏好折叠 | 降低日常修改门槛 | 基础优先，高级人格、设备与服务配置仍保留 |
| 首页只保留当前结果，任务入口按需显示 | 避免首页与顶部重复一件事 | 当前结果只呈现一次，按需进入任务详情；并发见最终 PRD |
| 完成待办时默认取消关联提醒并提供撤销 | 用户能立即恢复误操作 | 仅取消专为该待办创建、尚未投递的提醒；独立提醒不受影响 |

## 9. 如何指导下一步开发

先确认第 7 节的交互差异，并把本原型的代表性路径补入 PRD；不能因为原型没有出现某项功能，就把 R1 范围暗中删减。

| 开发顺序 | 最小可验收结果 | 界面是否需要扩张 |
| --- | --- | --- |
| 1. 统一人格与真实语音会话 | 改名/改提示词后下一轮一致；连续播音、打断、失败恢复及统一埋点可测 | 先复用原有页面与输入，不增加工作台 |
| 2. 真实记忆与事项 | 确认写入后重启仍存在，修改删除影响下一轮，临时会话边界正确 | 接入现有原型侧栏 |
| 3. 查询到记事再到提醒 | 真查询、有来源、候选可追问、按委托保存、具体时间调度；失败有部分结果和重试 | 使用连续委托现有呈现，不展示模型内部思考 |
| 4. 音乐与轻工作协作 | 真实音源/歌词/队列；语音和音乐互不打断；产物可续改保存导出 | 优先适配已有播放器和展开结果区 |
| 5. 补足 R1 完整范围 | 按 F01a 至 F11d、A01 至 A60 逐项验收，覆盖设置、引导、恢复与数据管理 | 只为缺失任务补充必要入口，再集中打磨布局 |

进入正式开发时，应将界面事件接到真实领域服务及回执，替换脚本数据源；不要把 `usePrototype.js` 的关键词路由和定时器搬成 Agent 架构。
