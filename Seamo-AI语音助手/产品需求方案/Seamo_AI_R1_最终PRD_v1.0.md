# Seamo AI 语音助手 R1 最终产品需求与开发规格

版本：v1.0 | 日期：2026-10-13 | 状态：产品行为已冻结，G0 服务资源待验证 | 首发：macOS、中文、单用户内部版

## 0. 文档效力与阅读方式

本文件是 R1 的**唯一产品行为口径**，供产品、设计、客户端、Agent、服务与测试共同使用。它规定用户能做什么、系统何时能宣称完成、状态如何转换、数据如何保存、异常如何恢复，以及每个阶段如何验收。`Seamo_AI_R1_产品需求文档.md` v0.5.1 中的 Prompt、Skill 全文、Schema 和 A01-A60 用例作为实施附件沿用；与本文件冲突时，以本文件为准。交互原型 `交互原型/R1/` 是体验参考，不是实现代码或真实服务验收证据。

需求状态分三类：**已决定**是必须实现的产品行为；**G0 待验证**是供应商、账号、协议或资源的真实可用性；**R2**不进入本期。未通过 G0 的能力不得以 mock 或脚本冒充完成；应保留未配置、不可用和可重试状态。本文件不承诺供应商当前接口能力或固定工期。

### 0.1 与 v0.5.1 及原型的最终差异

| 议题 | R1 最终口径 | 采用原因与研发边界 |
| --- | --- | --- |
| 页面结构 | 仍保留首页、音乐、记忆、事项、设置五类能力入口；日常查看记忆、事项和设置优先在陪伴空间中侧栏展开，窄窗口变覆盖层；复杂结果与长稿使用宽展开区 | 保持能力完整，但不形成五个割裂工作台；路由/容器是实现细节，切换不得重置会话、任务、播放器 |
| 音乐页进入 | 点歌成功后先在当前交流页显示迷你播放器；用户点开音乐或说“进入听歌页”才进入沉浸页。若用户已在音乐页则保持该页 | 播放与切页是两个不同动作；不能因为播放成功就中断正在进行的交流 |
| 事项与关联提醒 | 完成待办时，将**尚未投递且专为该待办创建**的提醒一并取消，并提供撤销；独立提醒不受影响。删除事项时必须确认关联提醒处理，默认保留，不自动取消 | 完成意味着无需再催办；删除只是移除记录，不代表撤销已承诺的提醒。实现要有 `linkPurpose`，不能仅凭 `itemId` 猜关系 |
| 长期记忆呈现 | “关于我”显示事实/偏好；“持续话题”显示可接续的主题与共同结论。两者均可查看来源、编辑、忘记 | 用户感知的是被理解和可延续，而不只是数据库里的几条事实 |
| 临时对话 | 不读、不写普通历史和长期记忆；明确保存事项或记忆必须先呈现影响范围，保存记忆需确认退出临时对话 | 临时是隔离承诺；不允许隐式持久化 |
| 任务结果 | 首页只显示当前最相关结果一次；结果不可见时才显示轻量全局任务入口；详情按需打开 | 结果不能同时占据首页、顶部和侧栏；关闭详情不取消后台任务 |
| 部分成功 | 已保存事项、提醒创建失败时，保留事项并只重试提醒；任何分项成功都不回滚成“全部失败” | 工具执行是可观察的分项事务，不能用一句模型回复覆盖真实状态 |
| 工作稿 | 一次修改应作用于同一 Artifact 的新版本；支持局部续改、撤销、保存、复制、Markdown/TXT 导出 | 讨论的价值在于可继续使用的结果，而非一段一次性回复 |

## 1. 产品定义

**一句话定位：**Seamo AI 是一个懂用户背景、能自然聊天，也能把生活和轻工作小事办成的桌面语音伙伴。它不是自动操作整台电脑的通用 Agent，也不以“会调用工具”代替实际结果。

### 1.1 核心体验原则

1. 陪伴先于流程。用户倾诉时先回应其具体内容，不擅自建待办、记忆或音乐队列。
2. 行动必须可核实。说“已记住”“已提醒”“正在播放”“查到”分别要求记忆提交、提醒调度、实际音频输出、可查看来源。
3. 能力按需浮现。用户先说话，细节在结果区展开；默认首屏不堆工具按钮和后台计划。
4. 一个伙伴，两种节奏。短对话即时回复；多步任务在后台运行，用户可继续交流、修订目标、停播或取消任务。
5. 记忆可见可控。长期事实与持续话题分层；用户能知道从哪里记住，能更正、忘记和开启临时对话。
6. 失败保留成果。部分成功要逐项给回执、可单独重试；不能重复创建已成功对象。

### 1.2 用户、情境与价值

| 情境 | 用户真实需求 | R1 可见价值 |
| --- | --- | --- |
| 下班后想聊天 | 被认真听见，不被工具流程打断 | 自然连续交流、适度回应、可打断、记住明确的重要背景 |
| 隔天接续 | 不想从头解释 | 找回相关主题和已有结论，接续而不伪造经历 |
| 查个现实问题 | 快速得到能信的答案 | 实时查询、来源、比较、未确认项、追问后修订 |
| 想到一件小事 | 帮忙记下并在合适时间提醒 | 便签/待办/一次性提醒的真实保存和改期取消 |
| 听歌陪伴 | 音乐不压过对话 | 实际播放、队列与歌词、边听边聊、沉浸页可主动进入 |
| 梳理思路 | 形成可继续修改的文字 | 讨论稿、局部修改、版本、保存与导出 |

### 1.3 范围

R1 必须覆盖 C01 自然交流、C02 个人记忆、C03 联网问答、C04 生活小事、C05 音乐陪伴、C06 轻工作协助，及统一的设置、诊断、数据管理。首发仅 macOS 中文内部使用。R2 才考虑跨设备、周期提醒、截图/文件理解、日历连接、自动简报、主动持续监测、系统级动作、购买/发送消息、插件市场和多 Agent 协作。R1 不后台持续读屏、不在彻底退出后执行云任务、不自动操作别的应用。

## 2. 端到端体验与页面

### 2.1 顶层用户路径

1. 首次打开：进入粒子球主界面，看到当前服务/麦克风状态；可跳过云配置使用已可用的本地页面，不把跳过当作授权。
2. 用户开始语音或输入文字：系统呈现聆听/识别/思考/播报的真实阶段；历史最多展开最近三轮，长回答按需展开全文。
3. 简单请求即时处理，复合请求创建有 ID 的后台任务；任务受理与完成分别反馈，用户可继续说话。
4. 结果在首页出现一次；查询候选、来源、比较、事项或讨论稿在展开区操作。关闭展开区不丢任务、草稿或输入。
5. 点歌实际开播后保留当前页面和迷你播放器；用户主动打开沉浸页，右侧动态歌词、粒子和曲目信息与真实音频时钟一致。
6. 下次启动显示一次可继续的话题/未完成任务提示；不会自动重播旧语音或再次提交旧写操作。

### 2.2 信息架构与交互合同

| 区域 | 默认呈现 | 展开操作 | 必须覆盖的状态 |
| --- | --- | --- | --- |
| 陪伴首页 P01 | 助手名、粒子、当前交流、轻量输入/语音、当前结果 | 最近交流、长回复、任务详情、历史 | 待机、连接、聆听、识别、思考、说话、后台进行、错误 |
| 音乐 P02 | 粒子、当前句歌词、临近上下文、紧凑封面/歌名/歌手/进度 | 搜索结果、音源、队列、收藏、歌词缺失信息 | 未播放、缓冲、播放、暂停、切曲、无歌词、源失效 |
| 记忆 P03 | 关于我、持续话题 | 单条来源、更正、忘记、搜索 | 空、加载、冲突、删除传播中、临时模式 |
| 事项 P04 | 按时间/类型分组的便签、待办、提醒及专注 | 编辑、改期、删除、撤销、错过提醒 | 保存中、部分成功、已完成、已取消、调度失败 |
| 设置 P05 | 称呼、声音、基础模式及服务状态 | 高级人格、设备、模型、记忆、勿扰、数据/诊断 | 未配置、鉴权失败、配额问题、设备不可用 |
| 结果展开区 O03 | 当前对象、关键摘要与操作 | 比较、来源、工作稿版本、保存/导出 | 空、加载、部分结果、重试、冲突、取消 |
| 全局任务入口 O05 | 仅当前结果不在视野时出现 | 活动任务、排队、暂停/取消/继续 | accepted、running、needs_input、paused、partial、done |

侧栏不是删除 P03-P05 的功能，只是默认呈现方式。窄窗口使用有实色背景的覆盖层，保持关闭、停止播报和输入可达。音乐页保持现有球体主体与深色审美，不加入装饰性环波、无依据的频率动画或堆叠卡片。可减少动态；音频和歌词功能不受影响。键盘焦点在输入框时 Space 输入空格，不触发录音。

### 2.3 用户可见文案边界

| 实际状态 | 可说 | 禁止说 |
| --- | --- | --- |
| 后台任务已受理 | “我先查一下，你可以继续和我说” | “查到了”“已经记好了” |
| 搜索只取得摘要 | “目前看到的是摘要，正文还没核实” | “我读了全文” |
| 事项提交成功、提醒失败 | “内容已记下，提醒还没设好；可以单独重试” | “都完成了”或把事项回滚成失败 |
| 播放器请求中 | “正在找可播放版本” | “正在播放” |
| 记忆召回超时 | “这次暂时没读到以前的记录” | “你从没告诉过我” |
| 系统通知已请求 | “提醒已到期，系统通知已请求” | “你已经看到了” |

## 3. 能力与业务需求

### 3.1 C01 自然交流（F01a-F03b）

**输入模式：**用户显式开启自动会话时才持续采集；默认待机不开麦。按住 Space 或按钮录音，松开发送；文字可独立发送。自动会话与按键模式切换需结束当前采集，不产生两个录音者。首次麦克风授权被拒绝仍允许文字聊天。设备拔插、失焦、快速连按不会把状态锁在聆听。

**应答规则：**固定人格版本、当前话题和少量相关记忆共同形成上下文。普通口语回复通常 1-3 句；倾诉时不强行建议。用户提出建议或行动后才切换。AI 身份保持明确，不声称是人类。设置中的助手名、称呼、风格和音色下一有效轮统一生效，包括问候、聊天、工具回执和试听；不得残留历史项目名。

**插话与取消：**用户真实开口经确认后，停止当前 responseId 的语音并清待播缓冲，保留已播范围；新输入成为新轮。噪声、音乐人声不能反复误打断。停止回答只停语音/生成；取消 taskId 才终止未提交任务；撤销已保存事项需另行执行实体操作。背景任务结果可以静默到卡片，不抢正在说话的用户。

**验收：**正常与打断/设备/权限/输入法/切页都可闭环；没有双播、旧音频复活、重复提交；首响和连续性按第 9 节测量，不以模型首 token 代替实际出声。

### 3.2 C02 个人记忆（F04a-F04e）

**三层记忆：**工作记忆是当前轮和当前任务上下文；情节记忆是普通会话历史及“持续话题”的阶段结论；语义记忆是稳定偏好、明确近况和共同结论。便签/提醒是独立业务实体，不自动等同于个人记忆。每条长期记忆记录内容、类别、来源、发生时间、有效期、授权方式、版本和删除状态；每个持续话题记录题目、最近结论、未解问题、关联会话/产物和状态。

**写入：**“记住……”显式指令提交后回执；自动记忆默认关，用户开启后异步提取明确事实，敏感内容必须当轮单独确认。一次情绪、推测人格、讽刺未澄清话语、网页上的人称句、模型自己生成的结论不得自动写成用户事实。重复事实合并，同一主题新结论产生新版本，不静默抹掉可追溯来源。

**读取：**按当前话题、实体、时间及有效性找相关内容，最多注入 5 条，不为凑数加无关事实。唯一相关主题直接接续；多个候选只澄清一个关键问题。最近事件过期后可作历史背景，不表述为当前计划。服务失败与真实没有记录必须区分。

**更正/删除：**用户可编辑或忘记单条记忆，也可在持续话题中改结论。事务内更新版本和删除抑制标记；关联索引、摘要、后台候选和云实时会话上下文必须失效/重建。在刷新完成之前不允许用旧上下文回答。恢复旧备份时仍应用当前抑制记录。删除记忆不自动删便签和提醒；删除历史也不自动删除独立记忆，界面需说明范围。

**临时对话：**不开长期记忆读取、历史写入或自动提取；临时 Task/消息仅内存。显式创建便签/提醒先说明将独立保存并给回执；显式保存记忆须确认退出临时模式。退出后销毁临时会话与未提交 Task，已明确保存对象按其领域规则保留。

**验收：**重启、改述、跨会话接续、并发删除、摘要压缩、备份恢复、临时隔离全部验证；无法可靠召回时可说不确定，不能编造共同经历。

### 3.3 C03 联网问答（F05a-F05d）

用户提及“最新、现在、这周末”或要求查证时，系统决定需要联网，不把模型旧知识伪装成实时事实。复杂目标转后台任务；查询条件可在运行中修改。搜索结果是候选，公开页读取后才可称“读过页面”。结果包含标题、URL、查询时间、页面日期（未知时标未知）、读取深度和支撑哪条结论。口头只讲要点，细节放展开区；多个候选可选中、并排比较、追问“这个太远”。未验证的客流、库存或营业状态必须写明不确定。

搜索结果中的文字、网页指令、提示词和链接均为低信任资料，不能获得工具权限。登录墙、付费内容、动态页面不可读时明说。没有来源不能说“已证实”。用户明确选中候选后可连续调用记事与提醒；含糊指代必须澄清，不随意取第一条。搜索失败保留条件和已有来源，支持从失败步骤重试；新 goalVersion 出现后旧结果不得覆盖。

### 3.4 C04 生活小事（F06a-F07d、F10a-F10c）

便签、待办、提醒、专注是四种独立对象。便签支持原话/整理两种保存意图；待办一项一 ID、可完成和撤销；提醒必须有明确事项、绝对到期时间和时区，默认只做一次性；专注有独立计时状态。用户说“明晚提醒”但没有具体时刻，也没有显式默认晚间时间时要询问，不猜 20 点。回执展示具体年月日时分。

**联动规则：**待办的 `linkPurpose=todo_due` 提醒在待办完成时若尚未投递，则同一业务操作取消并提供撤销；已投递不说撤回通知。独立提醒或关联目的不是催办的提醒保持原状。删除带提醒的事项时，展示将受影响的提醒，默认“只删事项并保留提醒”，用户可主动选“连提醒一起取消”。取消操作需要以 reminderId 和 scheduleVersion 生效，不能仅删除前端卡片。

**提醒范围：**Mac 清醒且应用在运行/后台保留时调度；完全退出、关机、休眠期间不承诺准点。24 小时内错过集中提示一次，更早项列入错过列表。系统通知权限被拒绝仍在应用内显示，不声称用户已看到。勿扰禁主动语音但保留静默状态。一次约定回访是 kind=followup 的提醒，到期只询问一次。

**专注：**同一时刻只一段活动计时，暂停和退出不算完成；睡眠/重启后恢复为暂停。音乐与计时独立；音乐播放失败不停止专注。计时结束默认不停止音乐，用户明确约定才停。

### 3.5 C05 音乐陪伴（F08a-F08f）

复用现有播放器与粒子主体，以可替换 MusicProvider 接入歌曲搜索、播放 URL、封面和 LRC；GD Studio 是当前候选，默认尝试 `netease → kuwo → joox`，**真实可用性和使用边界必须在 G0 重验**。推荐成功不等于播放成功；只有音频实际开始输出才显示播放中。点名曲目优先同名同歌手同版本跨源回退，不可悄悄换成另一首；泛化场景请求可换下一候选，并说明实际播放曲目。资源尝试有上限。

音乐页默认只有搜索框；提交非空关键词后显示搜索结果，可选音源并点击具体歌曲。结果含曲名、歌手、来源、封面和可用状态；旧请求晚到不得覆盖新结果。曲目、封面、歌词、音源以 `trackKey=source:id` 和 `playbackRequestId` 同步核对；封面失败不阻塞音频，无 LRC 显示曲目信息与推荐语，不伪造歌词。LRC 按音频时钟定位当前句，显示当前句及有限上下文，居中平滑移动；暂停冻结、拖动立即重算。搜索列表不常驻沉浸画面。

播放中仍可交谈。真实用户语音或助手播音使音乐平滑降到当前基准音量约 20%，活动结束约 300ms 后恢复；用户暂停、静音或改音量优先，不能擅自恢复。助手回答与歌词不争同一视觉焦点。队列、切曲、收藏和“不喜欢”独立真实保存；跳过一次不等于永久拉黑。

粒子球几何和总体空间位置不变。输入必须来自真实播放音频分析而非歌名或固定计时器；低/中/高频及节拍包络用于球体**内部**的分层亮度和小幅局部运动，中心柔和光源保留。柔和音乐变化克制，强节奏有清晰的有节拍点亮，但不得整体来回抽动、抖动或压过歌词。减少动态模式降低视觉强度，不修改音频。

### 3.6 C06 轻工作协助（F09a-F09c）

支持讨论取舍、整理用户粘贴文字、形成短稿与下一步。对事实性内容可按需联网，但用户提供的原文与搜索证据应区分。结果为可编辑 Artifact，有 `artifactId/version/sourceTurnId`；“第二段短一些”定位当前版本的第二段，仅修改目标段，其他内容原则上保留。模型新稿返回时若基准版本已变更，提示冲突，不覆盖用户最新手改。

支持撤销上一次修改、保存为便签/待办、复制及 TXT/Markdown 导出。保存同一 Artifact 的新版本更新关联记录，不生成副本；保存失败保留草稿。导出以用户确认的当前版本为准，取消系统文件对话框不是成功。R1 不读取文件/截图、不写入外部办公软件、不自动发邮件或发布内容。

## 4. Agent、算法与执行边界

### 4.1 组件职责

| 组件 | 做什么 | 绝不能做什么 |
| --- | --- | --- |
| 会话协调器 | 管理 turn/response、单一播音权、插话、当前焦点与任务事件 | 因切页而结束会话；把停止播音当取消任务 |
| 实时语音适配器 | 连续音频协议、文本/工具事件、打断与回注 | 将内部 ASR final 与用户实际停说混为同一时刻 |
| Task Harness | 多步目标、计划、工具观察、预算、修订与恢复 | 自行绕过工具执行器写库；输出隐藏推理给用户 |
| Context/Memory | 人格版本、相关历史/记忆、来源、删除抑制 | 将摘要作为新事实、复活已忘内容 |
| ToolExecutor | 权限、参数、版本、幂等、事务、真实 Receipt | 按模型自然语言直接宣称成功 |
| 领域服务 | 事项、提醒、音乐、搜索、产物的真实状态 | 由 UI 模拟成功回执 |
| 媒体协调器 | 语音/音乐优先级、降音、连续播放、音频时钟 | 每个分片开独立播放器、双播旧响应 |
| 展示层 | 原型交互接真实状态和可解释错误 | 用原型关键词路由或定时器充当 Agent |

选择框架的条件是能满足上述合同；v0.5.1 选择 Deep Agents/LangGraph 作为候选实施栈，G0 必须验证实际火山模型适配、工具调用、打包、检查点和默认工具关闭。框架名字不是验收条件，用户可观察能力才是。R1 不给模型终端、文件任意读写、浏览器账号操作或自装插件的权限。

### 4.2 单轮决策算法

```text
接收输入 → 判定当前 response/task/选中对象 → 装入人格版本与有效上下文
→ 模型可选择自然回应、询问一个关键缺项、即时工具、或 startTask
→ ToolExecutor 校验权限/参数/版本/明确委托 → 执行并取得 Receipt
→ 模型观察 Receipt，决定回复、修订下一步、部分完成或结束
→ 协调器检查最新 goalVersion、播音状态和结果去重 → 适时展示/播报
```

普通闲聊与“暂停音乐”无需强制规划。多步任务要保存可审计的行动摘要、状态和预算；模型可根据观察调整步骤，但不能扩大权限。用户说“只想聊聊”时，模型不能自动把情绪归类为记忆、任务或音乐意图。所有输入和工具回执都参与同一语义决策，不用固定关键词把请求永久锁死在一个子系统。

### 4.3 长任务与竞态

`startTask` 先持久化目标/条件并快速返回 `accepted + taskId`，后台运行与当前聊天分离。一个复杂 Task 活动，最多三个排队；暂停或等待用户可释放执行名额。用户修改条件触发 `goalVersion+1`：已提交的实体不回滚，未提交的写操作提交前再校验版本，旧只读结果可保留作资料但不作为最新结论展示。取消未提交步骤；提交状态不确定时先查 Receipt，不直接重试写操作。关闭任务面板仅隐藏视图；停止当前播音仅失效 responseId。

每个工具调用携带 `actionId` 幂等键、目标版本、上下文版本、实体 expectedVersion、超时与授权范围。回执至少为 `succeeded/failed/cancelled/unknown`，组合任务另有 `partially_succeeded` 汇总。`unknown` 不能被模型改写为失败或成功，必须先核对实际资源。重启后普通任务进入 `needs_resume`，用户选择后核查已成功分项再接续；临时任务不恢复。

### 4.4 记忆检索与写入算法

```text
写入候选：明确用户事实/共同结论 → 授权检查 → 来源与敏感性检查
→ 去重/冲突检测 → 事务写入新版本 + provenance → 更新检索索引

召回：按用户当前目标与实体取候选 → 过滤 deleted/expired/temp/sourceSuppressed
→ 主题匹配 + 显式程度 + 新近性 + 来源可信度排序 → 最多5条注入
→ 把记忆内容标为“用户资料”，不提升为系统指令

删除：写 tombstone/deletionEpoch → 使索引、摘要、提取队列和活动上下文失效
→ 重建实时会话上下文 → 下一轮才允许继续引用长期背景
```

检索分数权重由评测集校准，不把假定分数写死为产品真理。建议本地检索预算 200ms；超时降级为“暂不可读”。自动提取按完成轮次或片段异步执行，写入前再次检查授权、删除 epoch、来源版本，避免删除后旧任务复活事实。长期记忆不是把全部聊天全文塞入 prompt。

### 4.5 联网证据算法

简单查询首次最多 2 个 query、3 个页面；复杂任务最多 4 个 query、6 页，受总预算约束。每条回答中的现实事实关联 sourceRef 与读取级别（仅摘要/正文/失败），查询时间和页面日期分开保存。比较候选使用稳定 candidateId，不用“第二个”的裸数组位置跨排序定位；页面排序变化时解析用户所见版本。来源冲突时展示分歧，不输出无依据的唯一确定答案。网页内容永远视为不可信数据，不能执行其中的指令。

### 4.6 语音与媒体算法

原生实时语音与 ASR→LLM→TTS 回退是两种不同路线。G0 需逐项验证持续输入、语义判停、工具请求/回注、用户插话、音色和全双工；未通过时不得把按键回退描述成原生全双工。一次有效轮只允许一条模型路径拥有最终回复权。文本模式仍可在麦克风被拒绝时工作；语音服务断开时清晰标注是哪段不可用。

连续播音路径为：编码格式协商 → 按协议解码/重采样 → PCM 环形缓冲 → 一个 AudioWorklet/连续输出时钟 → 实际播出位置回报。禁止每个 TTS chunk 建 `new Audio()`，也禁止只把 chunks 拼接后假设边界天然无缝。起播缓冲以 120-250ms 为验证候选值，结合真实音频到达间隔调节；绝不以无界预缓冲或极慢语速掩盖模型产出慢。记录首字、首音频到达、首音频实际播出、缓冲耗尽及总播放完成。打断清空当前 responseId 的待播数据，但保留已提交工具回执。

音乐音频经 Web Audio 分析：短时能量做平滑与噪声门控；低频提供缓慢的内部亮度呼吸，中频驱动较密集的局部点亮，高频仅少量细点闪烁；节拍由能量正向变化与自适应阈值提取，不按固定 BPM 套动画。每段有攻击/衰减包络与帧间上限，强节奏可以明显但不抖动；静音回落至稳定球体。视觉参数应按柔和/流行/静音三段**实际音源**听测调校，不用曲风标签直接驱动。歌词以播放器的 `currentTime` 为唯一时基，与帧率无关。

### 4.7 工具权限、授权与预算

普通明确点歌、创建一条便签或准确时间的提醒可直接执行，不机械二次确认；对象多义、时间不明、批量删除、清理/恢复、临时模式持久化、覆盖冲突则必须确认或澄清。模型、网页、历史摘要都不能扩大当前工具集合。任务预算默认：轻任务最多 4 次模型决策/6 次工具；复杂任务 8 次决策/12 次工具/120 秒活动时间；连接失败最多 2 次自动重连，鉴权/配额错误不自动重试。达到预算给部分结果与继续入口，不能无限运行。

## 5. 数据、接口与状态合同

### 5.1 最小领域对象

| 对象 | 必需字段 | 所有权与规则 |
| --- | --- | --- |
| Persona | assistantName、userAddress、style、voiceId、version | 配置单一来源；与记忆分开 |
| Session/Message | sessionId、turnId、role、text、status、playedRange、createdAt、temporary | 普通持久，临时仅内存；已播与已生成分开 |
| Memory/Topic | memoryId/topicId、content/summary、category、sourceRefs、validity、version、deletionEpoch | 可更正、忘记、接续；来源可信与有效性可查 |
| UserItem | itemId、type(note/todo)、title、content、completedAt、version | 用户事项，不等于 Agent Task |
| Reminder | reminderId、itemId?、linkPurpose?、dueAtUtc、timezone、scheduleVersion、deliveryStatus | 独立实体与本地调度；提醒到期不等于已读 |
| Focus | focusId、durationSec、remainingSec、state、version | 独立计时，休眠恢复暂停 |
| Music | trackKey、playbackRequestId、playerState、positionSec、queueVersion、favorite/feedback | 曲目身份与异步资源版本一致 |
| Artifact | artifactId、sourceTurnId、body、version、savedItemId? | 局部续改与保存基于版本 |
| AgentTask/Run | taskId、goal、constraints、goalVersion、runId、status、budget、checkpoint | 后台任务；临时 Task 不落库 |
| Receipt/Delivery | actionId、entityId、status、actualResult、timestamp、channel | 客观执行记录；可去重、核查与恢复 |

主进程拥有密钥、领域服务、任务与存储；preload 仅暴露白名单类型化 IPC；渲染层只消费事件与调用明确动作。采用 SQLite 保存用户内容与 schemaVersion，系统安全存储保存密钥；原始录音默认不落盘，诊断默认不含密钥、聊天正文、原始音频。备份不含凭据；恢复先预检 schema 与覆盖范围，失败回滚，并合并现有删除抑制记录。彻底退出后不承诺云任务或提醒运行。

### 5.2 关键状态机

| 对象 | 合法主状态 | 关键转移约束 |
| --- | --- | --- |
| 语音轮 | idle → listening → transcribing/understanding → speaking → idle | 任意非 idle 可 error/cancel；插话生成新 turn，旧 response 不能复活 |
| Agent Task | accepted → running → needs_input/paused/queued → running → completed/partial/failed/cancelled | `accepted` 不是完成；版本更新后旧结果不能发布 |
| 提醒 | scheduled → due/delivered/missed/cancelled | 修改产生新 scheduleVersion；一次版本最多一条 Delivery |
| 待办 | open ↔ completed → deleted | completed 可撤销；专用未投递提醒联动取消/恢复 |
| 播放器 | idle → resolving/buffering → playing ↔ paused → ended/error | 只有实际音频输出才进入 playing；切曲旧请求失效 |
| 工作稿 | draft → revised → saved/exported | 新版保留旧版供撤销；导出取消不算成功 |

所有事件至少带 `eventId`、`occurredAt` 和适用的 `sessionId/turnId/responseId/taskId/runId/goalVersion/entityVersion`。重复事件按 eventId/actionId 去重。各进程时钟不直接相减：端到端以同一接收侧单调时钟记录，各内部阶段用 duration/span 关联 traceId。

### 5.3 不可变的完成条件

| 动作 | 真正完成条件 | 无法完成时 |
| --- | --- | --- |
| 保存记忆/事项 | 本地事务提交、返回实体 ID 与版本 | 保留用户原输入；不发成功文案 |
| 设置提醒 | 独立 Reminder 已提交且当前调度版本有效 | 已成功事项仍保留，可单独重试提醒 |
| 查证 | 至少有实际来源与可说明读取深度；不足时标 partial | 保留原查询和已取得证据 |
| 播放音乐 | 目标曲目实际输出音频，播放器时钟前进 | 不切换为假播放态；提供换源/重试 |
| 导出文稿 | 选定版本文件真实写入成功 | 取消/写失败保留稿件 |
| 任务结束 | 每个分项有可核验 Receipt，符合最新 goalVersion | 给部分结果、待补条件或明确失败 |

### 5.4 容量与默认参数

单次文字/正文/产物最多 8000 个 Unicode 码点；标题 80，助手名/称呼 20，人设 2000；按键录音每段 60 秒；记忆每轮最多 5 条；列表每页 20 条；本地召回建议 200ms；一次点名曲目资源尝试最多 3 次；专注默认 25 分钟、可设 60-10800 秒。以上是 R1 默认开发参数，若真实供应商限制更严格，以更严格限制提示用户，不静默截断。参数必须在配置、界面与测试中保持唯一口径。

### 5.5 相对 v0.5.1 的机器合同修订

旧版附件的 Schema 不是可以原样照搬的最终合同。G1 需在一处版本化 schema 中补齐下列字段、事务和测试；本表是强制迁移清单，不允许只改页面文案。

| 合同 | 必须修订的内容 | 必测约束 |
| --- | --- | --- |
| Reminder | 增加 `linkPurpose=todo_due/independent/other`、`cancelReason`、`previousScheduleVersion`；历史关联缺少目的时默认为 independent，不能自动取消 | 完成 Todo 只联动未投递的 todo_due；撤销完成仅恢复本次被联动取消且尚可重新调度的 Reminder |
| `notes.complete` | 返回 Todo 与关联提醒的分项 Receipt；若提醒状态未知，Todo 完成不能谎称提醒已取消，需标记待核查 | 同 actionId 重试不重复完成/取消；并发到期以实际 Delivery 为准 |
| `notes.delete` | 增加用户选择的 `reminderDisposition=keep/cancel`，确认时冻结关联提醒 ID 与版本 | 默认 keep；删除前关系变更须重新确认；不根据 `itemId` 级联数据库删除 |
| `music.play` 与视图事件 | 播放成功只更新 player 和迷你播放器；`openMusicView` 是独立 UI 事件 | 点歌不强制切页；已在音乐页时不返回首页；失败不展示 playing |
| Memory/Topic | Topic 保存结论版本、未解决问题和关联来源；Memory 保存删除抑制和有效期 | 话题继续与事实召回分层；删改后活动上下文失效 |
| Task/Result | 结果是否已在首页呈现、展示版本、任务入口可见性分开记录 | 关闭结果不取消 Task；同一结果不重复插卡/播报 |
| Artifact | `baseVersion`、段落目标、撤销引用、`savedItemId` | 旧模型回复不能覆盖新手改；二次保存更新同一记录 |
| TemporarySession | `temporary=true`、明确保存范围确认事件，不将正文/Task 检查点落库 | 临时结束销毁内存；明确保存对象保留且有回执 |

G1 还须把旧附件中“点歌后自动进沉浸页”“完成待办不取消提醒”“删除事项默认取消提醒”等相反用例替换为本文件口径，并保留回归测试证明旧行为已被有意识地迁移。已有用户数据迁移时，不得推断旧 Reminder 的 `linkPurpose=todo_due`；只有来源可核实才可标记，否则按 independent 保守处理。

## 6. 原型到真实产品的实现映射

| 原型动作 | 真实开发必须连接 | 不能照搬的演示逻辑 |
| --- | --- | --- |
| 语音按钮、模拟字幕 | 麦克风授权、采集、语音会话、转录/响应事件、连续播音 | 输入框注入示例文本、定时器假语音 |
| “持续话题” | Topic/Memory 真实来源、版本、召回与删除传播 | fixtures 中固定两三个话题 |
| 查询列表/比较 | SearchProvider、PageReader、证据/候选ID、任务事件 | 关键词匹配、固定地点卡与倒计时 |
| 保存并提醒 | Item 与 Reminder 分离、独立回执、失败单项重试 | 把提醒时间直接附在 Item 对象 |
| 音乐歌词、队列 | 真实 MusicProvider、播放器时钟、LRC、封面/源版本 | 模拟播放进度和虚构歌词 |
| 讨论稿局部修改 | Artifact 版本、真实模型编辑、冲突检查 | “第二段短一些”的固定脚本 |
| 原型本地保存 | SQLite、迁移、事务、备份与恢复 | 浏览器 localStorage 当生产数据层 |

开发必须先保留当前可启动版本与数据迁移回退点；不删除既有功能、不把原型直接替换正式 App。原有 Electron/Vue/Three.js、播放器与球体可以复用，但界面组件只接类型化领域事件。设置的人格、音色、音乐收藏与历史需要迁移方案与回滚验证。旧会话不能在同一轮混用两套语音/Agent 路径。

## 9. 质量指标与观测口径

| 指标 | R1 目标/门槛 | 测量方式与解释 |
| --- | --- | --- |
| 用户停说到**有意义的实际出声** | 正常网络 P50 ≤ 1.5s，P95 ≤ 3s，作为上线目标而非供应商保证 | 语义确认的停说/Space 松开至设备实际首个有效回答音；填充语不计。冷/热会话分开报 |
| 用户停说到屏幕首个有意义文字 | 与出声分开报告；不得混淆为模型首 token | 真实用户端事件，同一时基；文字可早于音频 |
| 插话确认到停声 | P95 ≤ 300ms | 另报用户开口至确认检测、噪声误打断率 |
| TTS/实时播音连续性 | 30 分钟混合听测无可复现逐字卡顿、重复、旧音频复活 | 记录 buffer underrun、分片到达、实际播放、自然停顿 |
| 本地播放器操作 | P95 ≤ 300ms | 从点击/已识别控制动作到实际生效，语音识别耗时另报 |
| 清醒运行提醒 | 到期偏差 ≤ 5s，同版本无重复投递 | 休眠、取消竞态和权限拒绝另列结果 |
| 显式记忆召回 | 固定改述集 ≥ 90%，删除/更正场景 100% | 至少 20 个跨会话案例；任何虚构共同经历记为失败 |
| 工具闭环 | 正常条件固定集 ≥ 95% | 成功必须有实体/来源/播放回执；外部故障另报全量成功率 |
| 陪伴自然度 | 内部盲评均分 ≥ 4/5，不低于旧版 | 贴切、口语、倾听、建议克制四维，保留失败样例 |

语音链路至少记录 `speech_end/space_up`、`turn_submitted`、`asr_final`（适用时）、`context_ready`、`model_request_start`、`first_meaningful_text`、`tts_first_input`、`first_audio_received`、`first_audio_played`、`buffer_underrun`、`turn_end`。任务至少记录 `task_accepted`、`goal_updated`、`tool_start/end`、`receipt_committed`、`task_completed`、`result_presented`。音频播放完成必须区分模型生成完成。跨进程阶段以 span 记录，不直接相减各自 `performance.now()`；供应商不暴露的内部时点标为不可观测，绝不补造。首次基线至少 100 次正常网络交互、30 次故障注入、耳机/扬声器/蓝牙分别听测。
